## 11. Story Engine 故事引擎设计

### 11.1 年龄适配体系

| 年龄段 | 词汇量 | 句长 | 页数 | 叙事结构 | 主题 |
|--------|--------|------|------|----------|------|
| 2-3 岁 | 50-100 词 | 3-5 词/句 | 10-12 页 | 重复+韵律 | 动物、颜色、形状、家庭 |
| 4-5 岁 | 200-500 词 | 6-10 词/句 | 16-20 页 | 问题→尝试→解决 | 友谊、勇气、探索、情绪 |
| 6-8 岁 | 500-1500 词 | 10-15 词/句 | 24-32 页 | 三幕式 | 冒险、公平、身份认同、学习 |

### 11.2 故事生成 Pipeline

```
用户输入
  ├─ 孩子档案：名字、年龄、性别、外貌、性格特征、兴趣
  ├─ 家庭结构：父母/兄弟姐妹/宠物/祖父母
  ├─ 故事主题：预设模板 or 自定义
  └─ 语言：单语/双语对照
      │
      ▼
  [Step 1] Story Architect（Claude API）
      │   输入：孩子档案 + 主题 + 年龄约束
      │   输出：故事大纲（每页摘要 + 情感弧线 + 教育元素）
      │   约束：年龄词汇表 + 安全 guardrails
      ▼
  [Step 2] Page Writer（Claude API）
      │   输入：大纲 + 每页详细指令
      │   输出：每页文本 + 对应插画 prompt
      │   约束：词汇级别 + 句长限制 + 韵律模式
      ▼
  [Step 3] Quality Check
      │   - 年龄词汇校验（超纲词替换）
      │   - 安全内容过滤（暴力/恐怖/不当）
      │   - 叙事完整性检查（开头→冲突→解决）
      │   - 个性化元素验证（名字/特征是否一致）
      ▼
  [Step 4] 输出
      ├─ 分页文本（JSON）
      ├─ 每页插画 prompt（含角色描述锚定）
      └─ 元数据（年龄级别、主题标签、教育元素）
```

### 11.3 情境模板库（Phase 3 — 50+ 场景）

| 大类 | 具体场景 | 核心叙事元素 |
|------|----------|------------|
| **家庭变化** | 新弟弟妹妹、离婚、再婚家庭、收养、寄养 | 安全感、归属感、爱不会变少 |
| **生活转变** | 搬家、转学、移民、上幼儿园 | 勇气、新朋友、家是人不是地方 |
| **情绪处理** | 愤怒管理、焦虑、害怕黑暗、分离焦虑 | 命名情绪、呼吸技巧、安全感 |
| **失去与告别** | 宠物去世、亲人去世、朋友搬走 | 悲伤是正常的、回忆是礼物 |
| **身份认同** | 混血身份、文化传承、性别表达、残障自信 | 你是独特的、不同是美丽的 |
| **健康** | 住院、打针、戴眼镜、食物过敏 | 勇敢、医生是帮助者 |
| **社交** | 被欺负、交新朋友、分享、团队合作 | 善良、边界、求助 |
| **成长** | 学骑车、第一天上学、学游泳、克服恐惧 | 练习、失败是学习、坚持 |

### 11.4 安全 Guardrails

```
三层过滤架构：

Layer 1 — System Prompt 约束（生成时）
  ├─ 禁止内容清单：暴力、恐怖、性暗示、歧视、自残
  ├─ 年龄适配规则：2-3 岁无冲突，4-5 岁温和冲突，6-8 岁可有挑战
  ├─ 文化敏感度：避免刻板印象、尊重多元文化
  └─ 正向引导：每个故事必须有积极结局或成长

Layer 2 — 后处理过滤（生成后）
  ├─ 关键词过滤（暴力/恐怖词库）
  ├─ 情感分析（确保整体基调积极）
  ├─ 年龄词汇校验（超纲词替换）
  └─ 名字/代词一致性验证

Layer 3 — 人工审核（上线前）
  ├─ 随机抽检 5%
  ├─ 用户举报处理
  └─ 文化顾问审核（多元文化内容）
```

### 11.5 多语言技术方案

| 方案 | 实现 | 优缺点 |
|------|------|--------|
| **并行生成** | 同一 prompt 分别生成中/英文 | 质量最高，成本 2x |
| **生成+翻译** | 生成主语言 → Claude 翻译 | 成本低，但韵律/文化适配弱 |
| **双语模板** | 预设双语句式结构 | 最快，但灵活性差 |
| **推荐**：Phase 2 用方案 B（成本可控），Phase 3 升级方案 A |

## 12. Illustration Engine 插画引擎设计

### 12.1 角色一致性技术栈（按鲁棒性排序）

| 层级 | 技术 | 一致性 | 速度 | 成本 | 适用场景 |
|------|------|--------|------|------|----------|
| **Tier 1** | LoRA 微调 | ★★★★★ | 慢（训练 15-30 min） | ~$1-2/次训练 | 系列角色、高复购 IP |
| **Tier 2** | IP-Adapter + ControlNet | ★★★★☆ | 快（无需训练） | ~$0.02-0.04/张 | MVP 默认方案 |
| **Tier 3** | FLUX.2 多参考图 | ★★★★☆ | 快 | ~$0.04-0.08/张 | 生产级方案 |
| **Tier 4** | Prompt 锚定 | ★★★☆☆ | 最快 | 最低 | 原型验证 |

**MVP 推荐**：Tier 2（IP-Adapter + ControlNet）— 无需训练，速度快，一致性够用。
**规模化后**：Tier 1（LoRA）— 为高频复购角色训练专属 LoRA。

### 12.2 画风模板矩阵

| 画风 | 适合年龄 | AI 实现难度 | 模型推荐 | 示例风格 |
|------|----------|-----------|---------|---------|
| 水彩 | 0-6 | 中等 | Flux + watercolor LoRA | 《猜猜我有多爱你》 |
| 扁平卡通 | 2-6 | 简单 | SD/Flux flat style prompt | 《小猪佩奇》风 |
| 蜡笔/手绘 | 3-7 | 简单 | SD crayon texture LoRA | 儿童涂鸦感 |
| 数字油画 | 4-10 | 困难 | Flux Pro + 后处理 | 《冰雪奇缘》绘本版 |
| 剪纸/拼贴 | 3-8 | 中等 | SD paper-cut LoRA | 中国传统剪纸风 |
| 国风水墨 | 4-10 | 中等 | Flux + ink painting LoRA | 敦煌/国潮风 |

**MVP 限定 3 种**：水彩 / 扁平卡通 / 国风水墨（覆盖中西方市场）

### 12.3 模型选型

| 维度 | FLUX.1 Pro / FLUX.2 | Stable Diffusion 3.5 | GPT Image 1.5 |
|------|---------------------|----------------------|----------------|
| 图像质量 | 最高 — 人体解剖准确 | 高 — 风格化优秀 | 高 — 想象力强 |
| 角色一致性 | 多参考图（最多 10 张） | IP-Adapter + LoRA 生态 | 仅 prompt 控制 |
| 文字嵌入 | 改善中 | 弱 | 最强 |
| 开源 | 否（API） | 是（本地+API） | 否（API） |
| 成本 | $0.04-0.08/张 | 自建 ~$0.01；API ~$0.02-0.05 | $0.04-0.08/张 |
| **推荐** | **主力模型** | **风格多样性备选** | **需要图内文字时** |

### 12.4 印刷就绪 Pipeline

```
AI 生成（1024-2048px RGB PNG）
    │
    ▼
Real-ESRGAN 2x-4x 超分辨率
    │   目标：300 DPI @ 8x10 inch = 2400x3000px 最低
    ▼
色彩空间转换
    │   RGB → CMYK（ICC Profile: FOGRA39 / SWOP）
    │   色域外检查：霓虹色/高饱和色标记警告
    ▼
排版组装
    │   出血：0.125 inch（3.175mm）四边
    │   安全区：文字/关键元素距裁切线 0.25 inch
    │   格式：TIFF（无损）或 PDF/X-4
    ▼
质量检查
    │   ├─ 角色一致性校验（面部特征比对）
    │   ├─ 色彩一致性（跨页色温/亮度）
    │   └─ 分辨率验证（≥300 DPI）
    ▼
输出
    ├─ 电子版：高清 PDF + Web 预览（sRGB）
```

## 15. 内容安全与合规体系

### 15.1 COPPA 合规要点（美国市场）

| 要求 | 实现 |
|------|------|
| 13 岁以下不得收集个人信息 | 仅收集家长信息，孩子档案由家长填写 |
| 可验证的家长同意 | 邮件确认 + 信用卡验证（FTC 接受） |
| 生物特征数据（2025 新增） | 照片上传用后即删，不存储面部特征向量 |
| 数据最小化 | 仅收集生成绘本必需的信息 |
| 删除权 | 家长可随时删除孩子档案 |
| 罚款 | $53,088/次违规 |

### 15.2 中国合规要点

| 要求 | 实现 |
|------|------|
| 《未成年人保护法》 | 不得推送不适内容 |
| 出版物内容审核 | 接入国内审核服务（阿里绿网/腾讯天御） |
| 个人信息保护法 | 不收集 14 岁以下未成年人信息，或取得监护人同意 |
| 网络出版服务许可 | 电子出版需要资质（可通过合作方解决） |
| ICP 备案 | 小程序/网站必须 |

### 15.4 AI 版权策略

| 风险 | 策略 |
|------|------|
| AI 生成图像不可版权 | 人工编辑/调整每张图 → 达到"人类创意贡献"门槛 |
| AI 训练数据争议 | 使用许可清晰的模型（Flux 商用许可 / SD 社区许可） |
| 用户上传照片 IP | 明确 ToS：用户授权使用照片生成角色，不用于其他用途 |
| 故事文本版权 | Claude API 生成文本 + 人工编辑 → 可版权 |
| 整体作品保护 | 以"编排和选择"申请版权（Elisa Shupe 先例） |

### 15.5 Prompt Injection 防护

| 攻击面 | 防护 |
|--------|------|
| 孩子名字字段注入恶意 prompt | 输入白名单过滤 + 长度限制 + 特殊字符剥离 |
| 自定义主题注入 | 主题从预设列表选择，自定义需审核 |
| 插画 prompt 注入 | 用户无法直接编辑 prompt，由系统生成 |
| API 滥用 | Rate limiting + 异常检测 |
