# 7阶段漏斗方法论

机会探测器的核心方法论：**漏斗式评估** — 在每个阶段投入最少精力获取最多信息，尽早淘汰不值得的机会。

## 设计原则

1. **渐进投入** — 前期花1天排除80%的差机会，比花1个月深入分析后才发现不行强100倍
2. **量化决策** — 每个门禁都有明确的通过标准，减少情绪化判断
3. **假设驱动** — 从 Day 1 开始就列出关键假设，整个流程就是在验证/证伪这些假设
4. **Kill ≠ 失败** — 快速 Kill 是成功的机会评估，浪费的是不 Kill 却坚持的时间

## 阶段详解

### Stage 1: SENSE 机会感知 (1-2周)

**目标**: 从噪声中提取信号

**输入**: 日常观察、行业动态、技术趋势、用户痛点
**输出**: 一页纸《机会简报》

**方法**:
- 多源信号采集（趋势、社交、专利、行业报告）
- 信号去重与聚类
- 桌面调研验证信号真实性
- 非正式专家访谈

**工具**: `trend_scanner.py`

**红线**: 如果找不到3个以上独立来源佐证同一信号，可能是噪声。

---

### Stage 2: SCREEN 初筛 (1-2周)

**目标**: 快速排除不值得深入的机会

**输入**: 机会简报
**输出**: 初筛评分卡 + Go/Kill 决策

**方法**:
- TAM/SAM/SOM 估算（量级判断，非精确数字）
- 竞争格局快速扫描（直接竞品 + 间接竞品）
- 能力差距评估（我能做吗？多久能做？）
- 粗算单位经济（LTV/CAC > 3？毛利率 > 50%？）

**工具**: `market_sizer.py`, `competitor_matrix.py --mode quick`, `opportunity_scorer.py`

**门禁 G1**: 综合评分 > 60/100 → Go; 否则 Kill

**核心问题**:
- 市场够大吗？（TAM > $100M）
- 能赢吗？（有差异化空间）
- 值得做吗？（经济模型基本可行）

---

### Stage 3: ANALYZE 深度分析 (2-3周)

**目标**: 深入理解市场、竞争、价值链，构建财务模型

**输入**: 初筛通过的机会
**输出**: 《财务分析报告》+ 投资决策

**方法**:
- 市场细分 + 客户画像深化（JTBD框架）
- 竞品深度拆解（Top 3-5）
- 价值链绘制 + 切入点分析
- 风险登记簿（概率 × 影响矩阵）
- 财务模型（3年月度预测 + 敏感性分析）

**工具**: `competitor_matrix.py --mode deep`, `financial_model.py --mode full`

**门禁 G2**: NPV > 0 且 IRR > 期望收益率 → Go; 否则 Kill 或 Pivot

---

### Stage 4: VALIDATE 验证 (2-4周)

**目标**: 用最小成本验证致命假设

**输入**: 关键假设清单（从分析阶段提取）
**输出**: 验证结果报告 + Go/Pivot/Kill 决策

**方法**:
- 提取 "Leap of Faith" 假设（如果错了，整个项目就不成立的假设）
- 选择最小 MVP 类型（落地页、视频、魔法师型……）
- 定义红线指标（通过/失败标准提前约定）
- 执行 MVP + 收集数据
- 对照红线指标做决策

**工具**: PostHog（埋点）, GrowthBook（A/B测试）

**门禁 G3**:
- 所有致命假设通过 → **Go**
- 部分失败但可调整 → **Pivot**（修改方向重新验证）
- 核心假设证伪 → **Kill**

---

### Stage 5: PLAN 商业计划 (1-2周)

**目标**: 制定可执行的启动方案

**输入**: 验证通过的机会
**输出**: 完整商业计划 + 启动批准

**方法**:
- Business Model Canvas
- 定价策略设计
- 护城河策略
- GTM（Bull's Eye 框架选渠道）
- 资源与预算规划
- 风险应急计划

**门禁 G4**: 资金到位 + 风险可控 → 启动批准

---

### Stage 6: LAUNCH 执行启动 (持续)

**目标**: 产生首笔收入

**关键里程碑**:
1. 团队到位
2. 首阶段交付
3. 首笔收入 ← **最关键的验证点**

---

### Stage 7: MONITOR 监控迭代 (持续)

**目标**: 持续跟踪、迭代优化

**方法**:
- 搭建指标看板（Metabase）
- 定期复盘（周/月）
- 根据数据迭代产品和策略

---

## 角色定义

| 角色 | 职责 | 典型活动 |
|------|------|---------|
| 分析师 | 调研、数据分析、模型构建 | 趋势扫描、市场估算、财务建模 |
| 决策者 | 方向判断、Go/Kill 决策 | 门禁评审、假设优先级排序 |
| 执行者 | MVP 构建、方案落地 | 原型开发、渠道测试、团队组建 |

个人创业者可能身兼三个角色，但每个环节要明确当前戴哪顶帽子。

## 与其他框架的对比

| 框架 | 适用场景 | 本框架的区别 |
|------|---------|-------------|
| Lean Startup | 创业验证 | 增加了前期市场分析和财务建模 |
| Stage-Gate | 产品开发 | 轻量化，适配知识型工作 |
| Discovery-Driven Planning | 不确定性管理 | 增加了工具化和自动化 |
| Business Model Canvas | 商业模式设计 | BMC 是本框架 PLAN 阶段的一个工具 |
